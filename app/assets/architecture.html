The big picture (V1)

From dispute to reviewed response

A fake merchant (the synthetic world) produces disputes and the records behind them. The agent reads those records and proposes fight, accept or escalate. A person reviews every response before it would reach the issuer. Separately, the eval harness knows the right answer for every case and grades every version the same way. The agent never sees the answers.

Walkthrough

One dispute, two versions

Case GEN-005: a Mastercard “goods not received” dispute for $145. The webhook says reason category general; the issuer's note says the item never arrived. Tracking, a delivered scan and an address match are on file; there is no signature or photo.

V0

One call decides: escalate, wrong

  1. Everything goes in one prompt

    All the records, the policy and the list of evidence types. No rules table, so the model must guess which evidence this reason code requires.

  2. The model guesses

    It treats the missing signature or photo as required, computes EV = 0.55 × $145 − $35 = $44.75, and escalates under rule 6.

  3. Graded wrong

    The answer key says fight: a signature or photo only strengthens a case. 20 of the 51 “fight” cases went the same way in V0.

V1

Code decides: fight, right

  1. The model reads the text

    It confirms the category (item not received) and finds no customer acknowledgement, admission or remedy in the messages.

  2. Code applies the policy

    The rules table says tracking, delivered scan and address match are required: all present. P(win) 0.70; EV = 0.70 × $145 − $35 = $66.50; no trigger applies, so rule 7: fight.

  3. The model writes the letter

    From a verified fact sheet. The calibrated judge passes it; it goes to the review queue for a person to approve.

The decision

Fight, accept or escalate

Fighting costs money, so the policy starts from expected value. The numbers are product decisions stored in config/decision.toml. In V0 the model applied these rules; in V1 code applies them, and the answer key uses the same file.

expected value = P(win) × disputed amount − $35.00  ($15 processor fee + $20 analyst time)

Rules apply in order. The first one that matches decides.

1Response deadline already passedaccept
2Amount is $750 or moreescalate
3Customer has 2+ other disputes in the past 365 daysescalate
4Records show the merchant is at fault (package lost, return never refunded)accept
5Expected value is zero or negativeaccept
6Under 72 hours left, records conflict, or required evidence missingescalate
7Anything elsefight

Rule 5 comes before rule 6 on purpose: a low-value case isn't worth a person's time. The catch is that a wrongly “missing” evidence item can push EV below zero and get a winnable case accepted with nobody looking, so the harness counts these wrongful auto-accepts separately. V0 had 14; V1 has none.
