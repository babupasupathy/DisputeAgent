The big picture

Three parts, one direction

A fake merchant (the synthetic world) produces disputes and the records behind them. The agent reads those records and decides what to do. The eval harness knows the right answer for every case and grades the agent. Answers flow left to right only: the agent code never imports the eval code or sees the labels.

Walkthrough

Follow one dispute

Case GEN-005 from the smoke test: a Mastercard “goods not received” dispute for $145.

  1. synthetic world

    A dispute arrives

    The generator created an order, a shipment with tracking events, support messages and a dispute record. The webhook says reason category general, but the issuer's note says the item never arrived.

  2. agent

    Every record is collected

    full_context() calls all seven read functions: dispute details, deadline, order, tracking, customer history, support messages, refunds. V0 does not choose what to look at; it gets everything.

  3. agent

    One prompt goes to Claude

    The system prompt holds the merchant's decision policy (built from decision.toml), grounding rules and the list of evidence types. The records are pasted in as JSON. The model must answer in a fixed JSON shape.

  4. agent

    The model answers

    It reclassified the dispute as Mastercard 4853 item not received, computed EV = 0.55 × $145 − $35 = $44.75 (positive), saw that signature/photo proof and customer acknowledgement were missing, and chose escalate under rule 6. It also wrote a draft letter for a human to review.

  5. eval harness

    The answer is graded

    The runner stores the answer, token counts, cost ($0.03) and latency. The scorer compares category, evidence lists and decision against the label, and checks that every ID, amount and date in the draft appears in the records. The Opus judge scores the draft letter.

    Verdict: wrong. The label says fight. For Mastercard 4853 the required evidence is tracking, a delivery scan and an address match, and all three were present. Signature or photo proof only strengthens a case; it is not required. V0 has no rules table, so it treated an optional item as required and escalated a winnable case. 20 of the 51 “fight” cases went the same way in the full run.

The decision the agent must make

Fight, accept or escalate

Fighting costs money, so the policy starts from expected value. The numbers are product decisions stored in config/decision.toml, not in code. The labeler uses the same file to compute the right answers.

expected value = P(win) × disputed amount − $35.00  ($15 processor fee + $20 analyst time)

Rules apply in order. The first one that matches decides.

1Response deadline already passedaccept
2Amount is $750 or moreescalate
3Customer has 2+ other disputes in the past 365 daysescalate
4Records show the merchant is at fault (package lost, return never refunded)accept
5Expected value is zero or negativeaccept
6Under 72 hours left, records conflict, or required evidence missingescalate
7Anything elsefight

Rule 5 comes before rule 6 on purpose. A wrongly “missing” evidence item can push EV below zero and get a winnable case accepted with no human looking at it. The harness counts these wrongful auto-accepts separately.

How the agent is graded

What the harness measures

DimensionQuestion it answersHow
ClassificationDid it identify the network, reason code and category?Exact match
EvidenceDid it list the right evidence as present and missing? How often did it call real evidence “missing”?Exact match
DecisionRight action? How many wrongful auto-accepts, and how many dollars?Exact match
EscalationWhen it escalates, should it have? Does it catch the cases that need a human?Precision / recall
No fabricationDoes every ID, amount, date and tracking number in the draft appear in the records?Regex against the records
Draft qualityIs the letter on point, grounded, clear and well formatted?Opus judge, 1–5 per criterion
Tool useDid it look up what it needed and skip what it didn't?Call trace (from V1 on)
Cost and speedDollars per case, p50/p95 latency, which model actually servedLogged per call

The harness was checked before any real run. An oracle that reads the labels scores 100%. Deliberately breaking 10% of its answers makes exactly those 17 cases fail. The judge's grades count as uncalibrated until a person grades a sample of 40 drafts for comparison.
