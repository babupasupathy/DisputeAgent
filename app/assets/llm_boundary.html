Dispute Agent · who does each job

LLM Boundary Map

In V0, one Sonnet call did almost everything between fetching the records and the human review. Most of that work is lookups and arithmetic on database fields, which code does exactly, instantly and for free. V1 moved it to code and kept the model only where text has to be read or written. This page shows each step in both versions, and what the change measured.

What it saved

Cost and speed per case

Measured · V0
$0.023

One Sonnet call per dispute: about 5,900 input and 1,750 output tokens. 10.6 s typical.

Measured · V1
$0.012

Half of V0. A reading call when there is text to read, a letter only for fight and urgent escalations, nothing for accepts.

Measured · V1 speed
2.4 s

Typical, down from 10.6 s. Accepts and briefs return almost instantly; cases with a letter take about 10–12 s.

At about a cent a case, model cost is small next to the $35 it costs to fight a dispute. The bigger wins were accuracy and being able to name the rule behind every decision.

The catch, and how it was handled: the eval grades the code against itself

The answer key and V1's decision code implement the same written policy, so with correct inputs V1 scores 100% on decisions by construction. That number alone proves little.

So the meaningful tests moved to what the model still does. Reading: 30 deliberately messy, hand-written support threads labelled blind by the owner; after three owner rulings on what counts as implied, every field right on 29 of 30. Letters: 20 fresh V1 letters graded blind, which also exposed a synthetic-data bug the 162-case score could never have shown.

How it went

The rollout, step by step

  1. Decision layer to code: done

    Rules table, field checks, P(win), EV and the 7 rules. Decisions 76% → 100%; winnable cases escalated 20 → 0; wrongful auto-accepts 14 → 0.

  2. Letters only where needed: done

    Accepts get a one-line note. Conflict and missing-evidence escalations get a brief, with a letter on demand guarded against the merchant's own admissions. Cost per case −50%.

  3. A smaller model for reading: tested, not adopted

    Haiku matched Sonnet on every decision-driving fact but missed more implied receipts. Decided on ROI: Sonnet stays.

  4. Cheaper judging: still to do

    Batch API and skipping unchanged letters are free wins. A Sonnet judge only if it matches Opus on the 60 human-graded letters.

Measured figures come from evals/results/v0 and evals/results/v1 (162 synthetic cases each). Prices: Sonnet 5.5 $2 / $10, Opus 5.5 $4 / $20, Haiku 5.5 $0.10 / $0.50 per million input / output tokens; Batch API is half price. All data is synthetic.
